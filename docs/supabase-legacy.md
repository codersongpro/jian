# 이전 Supabase 구현 참고 자료

이 문서는 GitHub 파일 관리 방식으로 전환하기 전의 구현 기록입니다. 현재 공개 전시와 관리자 안내는 Supabase를 사용하지 않습니다. 아래 설정만으로 현재 공개 전시의 데이터 소스가 바뀌지는 않습니다.

# JIAN’S UNIVERSE

Vercel에 배포하는 단일 페이지 디지털 전시관입니다. Next.js·React·TypeScript, CSS/SVG 모션, Web Audio, Supabase 인증·데이터베이스·비공개 파일 저장소를 사용합니다.

## 로컬 실행

Node.js 24와 npm을 사용합니다.

```bash
cd /workspace/jian
npm ci --cache /workspace/.cache/npm
npm run dev
```

클라우드 작업은 이미 격리되어 있으므로 이 체크아웃을 그대로 사용합니다. 별도 Git worktree를 만들 필요가 없습니다. 일반 로컬 컴퓨터에서는 `npm ci`만 사용해도 됩니다.

Supabase 환경변수가 없으면 배포 모드의 공개 화면은 **공개 승인된 작품이 없는 전시 준비 상태**입니다. 관리자 화면은 연결 안내를 보여 줍니다. 가짜 로그인·가짜 저장은 제공하지 않습니다. 실제 제공 자료는 아래의 개발용 검토 모드에서 볼 수 있습니다. Supabase가 설정되었지만 조회에 실패하면 전시 자료를 불러올 수 없다는 상태를 표시합니다.

## Supabase 연결

1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql` 전체를 **한 번** 실행합니다. 이미 실행한 스키마에 그대로 반복 실행하지 않습니다. 트랜잭션이므로 도중 오류가 있으면 전체 적용이 취소됩니다.
2. Authentication → Users에서 관리자 계정을 직접 만듭니다. 공개 회원가입은 사용하지 않으므로 Authentication 설정에서 신규 가입도 비활성화하는 것을 권장합니다.
3. 그 사용자의 UUID를 확인한 뒤 SQL Editor에서 다음을 실행합니다.

   ```sql
   insert into public.admin_users(user_id) values ('실제-사용자-UUID');
   ```

4. `.env.example`을 `.env.local`로 복사하고 프로젝트 설정에 표시된 실제 값을 **로컬 환경 또는 배포 환경의 보안 설정에서만** 입력합니다.

   | 변수                            | 용도                                                   |
   | ------------------------------- | ------------------------------------------------------ |
   | `NEXT_PUBLIC_SUPABASE_URL`      | 프로젝트 HTTPS URL                                     |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저용 anon 공개 키. RLS 필수                      |
   | `SUPABASE_SERVICE_ROLE_KEY`     | 공개 승인된 원본을 서버에서 전달할 때만 쓰는 서버용 키 |

   서비스 키를 `NEXT_PUBLIC_` 변수에 넣지 마세요. 키 값은 저장소·문서·채팅에 기록하지 않습니다. 공개 키와 서비스 키를 서로 바꾸지 마세요.

5. 개발 서버를 재시작합니다. 공개 환경변수는 빌드에 포함되므로 프로덕션은 다시 빌드해야 합니다.
6. `/admin`에서 로그인하고 작품을 저장합니다. 로그인 성공과 관리자 권한 확인은 별개입니다. `admin_users`에 없는 계정은 편집할 수 없습니다.

## 작품과 미디어

- 방문자는 `/`에서 분야 필터·연도별 타임라인·별자리·일반 목록을 탐색합니다. 작품 상세는 키보드를 지원하는 팝업입니다.
- 관리자는 제목·분야·연도·소개·시 원문·YouTube 주소·대표 작품 순서·모션·공개 상태를 편집합니다. 대표 순서는 0부터 작은 값이 먼저 표시되며 비워 두면 대표 작품에서 제외됩니다.
- 작품을 저장한 뒤 이미지나 오디오를 업로드합니다. 최대 50MB이며 JPG·PNG·WebP·MP3·WAV·OGG·M4A를 지원합니다. SVG·HTML·외부 임의 주소 파일은 받지 않습니다. 업로드는 브라우저에서 인증된 Supabase Storage로 직접 전달되어 Vercel 요청 본문에 큰 파일을 싣지 않습니다.
- 업로드는 기본 비공개입니다. `사용 권한 확인` 후 `공개 승인`을 선택해야 공개할 수 있습니다. 작품 자체도 공개 상태여야 그 작품의 미디어가 노출됩니다. 실제 연주·사진·음성의 활용 동의는 관리자가 확인해야 합니다.
- 원본은 재인코딩하지 않습니다. 공개 이미지는 원본 비율을 유지하고 화면 밖에서 지연 로딩합니다. 대용량 원본 이미지는 별도 최적화 사본을 준비하면 전송 성능이 개선됩니다.
- `/api/media/[id]`는 요청마다 공개 상태를 RLS로 확인하고 원본을 스트리밍합니다. Range 요청도 같은 검사를 거치며 응답을 캐시하지 않습니다. 서버용 서명 URL은 방문자에게 전달하지 않습니다. 이미 다운로드한 사본이나 열린 전송의 바이트는 공개 취소로 회수할 수 없습니다.
- 관리자 `원본 확인`은 관리자 권한을 확인한 뒤 60초 유효 링크를 만듭니다. 이는 비공개 검토용 링크이며 외부에 공유하지 않습니다.
- 작품 삭제는 미디어 등록도 제거하지만 원본 파일은 Storage에 보존합니다. 필요하면 Storage에서 별도로 정리합니다. 파일의 개별 삭제 버튼은 등록과 원본 모두 삭제합니다.
- 전시실 설정에서 배경과 테마를 올리고 승인한 뒤 선택합니다. 작품 오디오는 작품별로 등록하며 장식 테마와 별개입니다. 기본값 복원은 파일을 삭제하지 않습니다.

## 모션과 사운드

첫 접속은 무음이며, 저장된 설정이 있어도 페이지를 새로 열면 소리가 자동 재생되지 않습니다. 헤더에서 사운드를 명시적으로 켜야 합니다. 배경 음악·효과음·볼륨·모션 설정을 따로 보관합니다. 저장소를 사용할 수 없는 브라우저에서도 동작합니다.

기본 테마 **Little Notes**는 앱에서 합성한 약 18초의 선율입니다. 제삼자 음원이나 실제 지안이 연주를 사용하지 않습니다. 오디오 엔진은 소리를 켠 뒤 지연 로드됩니다. 직접 업로드한 테마로 교체할 수 있습니다.

실제 작품 오디오나 YouTube 재생 시 배경 음악이 멈춥니다. 탭을 벗어나면 미디어도 중단하며 돌아왔다는 이유만으로 자동 재개하지 않습니다. 배경 음악은 감상 설정에서 직접 재개할 수 있습니다. YouTube는 `영상 불러오기`를 누른 뒤 공식 IFrame API를 불러옵니다. 네트워크에서 YouTube가 차단되면 안내와 원문 링크를 표시합니다.

운영체제의 `prefers-reduced-motion`과 화면 내 모션 최소화를 지원합니다. 모바일에서는 지속적인 장식 모션을 줄입니다. 스캔 기능은 원래 작업지시서가 없으므로 임의로 추가하지 않았습니다.

## Vercel 배포

1. GitHub 저장소를 Vercel에 연결하고 Framework Preset을 **Next.js**, Root Directory를 이 프로젝트 루트로 선택합니다.
2. Node.js 버전은 **24.x**로 설정합니다. Install Command는 `npm ci`, Build Command는 `npm run build`입니다.
3. 위 세 환경변수를 필요한 Production/Preview 범위에 등록합니다. Preview에서 실제 자료를 다룰 경우 승인·공개 상태에 주의하고 별도 테스트용 Supabase 프로젝트를 사용하는 것이 좋습니다.
4. 배포 후 `/`와 `/admin`을 확인합니다. 공개 키 변경 후에는 재배포가 필요합니다. Supabase Auth Site URL을 배포 주소로 설정합니다.
5. 아래 실서비스 검증을 수행한 후 실제 작품을 공개합니다. 이 저장소를 작성한 클라우드 작업에서 실제 Vercel 배포는 실행하지 않았습니다.

필요한 네트워크 대상은 npm 레지스트리, 실제 Supabase 프로젝트 호스트, 선택적으로 YouTube API·영상 제공 호스트입니다. 제한된 클라우드 네트워크에서는 기존 허용 목록을 유지한 채 해당 호스트만 추가합니다. 프로젝트 URL이 정해지기 전에 임의의 서비스 키나 광범위한 네트워크 규칙을 만들지 않습니다.

## 검증

```bash
npm test
npm run typecheck
npm run build
npm run test:e2e
```

브라우저 테스트는 **Supabase 미설정 프로덕션 서버(3000)**와 **제공 자료가 있는 개발용 검토 서버(3001)**를 함께 대상으로 합니다. 클라우드에서는 `/usr/bin/chromium`을 사용합니다. 다른 컴퓨터에서는 Chromium을 설치하고 `CHROMIUM_PATH`를 지정하거나 Playwright 설정에서 번들 브라우저 경로를 사용합니다. 테스트가 필요할 때 Playwright가 두 서버를 시작합니다. 이미 실행 중인 서버가 있다면 같은 빌드의 서버인지 확인합니다.

실서비스 연결 후 별도로 확인할 항목:

1. 익명·일반 사용자에게 쓰기가 거부되고 등록된 관리자만 편집 가능.
2. 비공개 작품·미디어는 ID를 알아도 조회와 원본 접근 불가.
3. 이미지·오디오를 원본으로 올린 뒤 승인하면 공개되고 취소 후 새 요청·Range 요청은 거부됨.
4. 배경·테마·대표 작품 설정이 새 방문에 반영됨.
5. 실제 YouTube 재생, iOS Safari 오디오, 대용량 파일 전송이 배포 환경에서 정상 동작.

현재 확인된 결과와 연결이 필요한 항목은 `docs/validation.md`를 참고하세요.

## 제공된 실제 자료와 검토 모드

사용자가 제공한 `jian-public-assets.zip`의 작품 9묶음·본문 전사·그림/사진·링크 6개를 연결했습니다. 원래 자료의 `publish_ready:false`, 날짜 근거, 전사/편집 여부와 미확인 항목을 유지했습니다. 첨부 문서의 외부 대화·Drive 검색 범위는 자료 작성자의 기록이며, 이 코드 작업에서 그 검색을 다시 수행한 것으로 주장하지 않습니다.

현재 클라우드에서는 `.env.local`의 `CONTENT_REVIEW_MODE=1`과 `npm run dev`로 실제 자료 검토 화면을 실행할 수 있습니다. `NODE_ENV=development`에서 명시적으로 켰을 때만 작동합니다. **프로덕션에서는 같은 플래그가 있어도 검토 화면과 파일 경로가 비활성화됩니다.**

`content-bundle/`은 공개용 후보 자료의 로컬 보관함이며 Git에서 제외했습니다. `public/`에도 넣지 않았습니다. 현재 클라우드에 원래 ZIP 구조대로 보관되어 있습니다. 다른 컴퓨터에서 검토하려면 해당 ZIP을 이 폴더에 풀어 주세요. 코드만 받은 환경에서는 승인된 Supabase 콘텐츠로 운영하며 후보 자료를 자동으로 공개하지 않습니다. 로컬 자료 검증 테스트와 검토용 브라우저 테스트에는 이 폴더가 필요합니다.

검토 화면은 원래 썸네일, 여러 페이지, 동시/영어 편지 전사, 가족법전 발췌, 앱 계획서와 자료 메모를 보여 줍니다. 제작일이 없는 항목에는 연도를 만들지 않습니다. 표시된 연도 중 Drive 등록일과 판권일은 창작일로 단정하지 않으며 상세에서 날짜 근거를 확인할 수 있습니다. YouTube 여섯 링크는 지정 순서를 보존하고 확인되지 않은 제목·장면·출연자를 지어내지 않습니다. 자동 임베드하지 않습니다.

### Supabase로 비공개 가져오기

1. 위 절차로 Supabase 스키마와 관리자 계정을 준비합니다. 이번 프로젝트는 아직 Supabase가 없으므로 **현재의 최신 `schema.sql`**을 설치하면 됩니다.
2. 로컬 검토 자료가 있는 이 클라우드 또는 개발 환경에서 Supabase 환경변수를 설정하고 서버를 재시작합니다.
3. `/admin`에 로그인하고 **제공 자료 9묶음** 탭을 엽니다.
4. 작품별 **비공개로 가져오기**를 누릅니다. 본문·출처 메모와 제공된 이미지 파생본을 비공개로 저장합니다. 원본 PDF나 자필 원파일로 표시하지 않습니다. 기존에 가져온 작품은 덮어쓰지 않습니다.
5. 작품 관리에서 전사·편집, 날짜 근거, 미디어 사용 권한과 공개 범위를 확인한 뒤 작품·미디어 각각의 공개를 승인합니다. 작품만 공개하고 이미지 승인을 빠뜨리면 이미지가 노출되지 않습니다.
6. 그 후 Vercel을 연결하면 승인된 Supabase 작품을 표시합니다. 후보 파일 폴더를 Git에 올릴 필요가 없습니다. Vercel에 후보 폴더가 없으면 관리자 자료 목록은 비어 있으며, 가져오기는 자료가 있는 검토 환경에서 수행합니다.

이전 가져오기가 중단된 비공개 작품이 있으면 오류로 안내하며 기존 자료를 덮어쓰지 않습니다. 작품 관리와 Storage에서 중단된 자료를 확인한 뒤 정리할 수 있습니다.

`jian-private-review.zip`은 도구의 파일당 32MiB 전송 한도를 초과해 다운로드하지 못했습니다. 따라서 그 안의 원본 PDF·DOCX·HWP 등은 반영하거나 검수한 것으로 표시하지 않습니다. 후속 처리를 위해서는 각 파일 또는 분할 ZIP을 32MiB 이하로 제공해야 합니다. 비공개 원본은 공개 경로나 Git 저장소에 넣지 않습니다.

내부 검수 메모는 `work_reviews` 테이블에 분리하며 관리자에게만 읽기·쓰기 권한을 부여합니다. 공개 작품의 `provenance`에는 분야·자료 날짜·날짜 근거·표시 이름·근거 수준·전사/편집 안내만 저장할 수 있도록 데이터베이스 제약을 둡니다. 작품을 공개해도 원래의 비공개 검수 기록이 일반 방문자에게 전달되지 않습니다.
