# JIAN'S UNIVERSE 설계안

작성일: 2026-10-18 (Asia/Seoul)

## 목적과 확정된 요구사항

지안이의 글·그림·과학·수학·음악·발레 작품을 연결하는 조용한 디지털 전시관을 만든다. 사용자는 Vercel 배포, 방문자용 단일 랜딩페이지, 관리자 기능을 요청했다. 첨부한 모션·사운드 추가 개발지시서 전체를 기능 기준으로 사용한다. 원래 통합 개발지시서와 실제 작품 자료는 제공되지 않았으므로 그 내용을 임의로 만들어 사실처럼 표시하지 않는다.

현재 `/workspace/jian`은 커밋과 파일이 없는 저장소다. 다음 내용은 검토를 위한 설계이며 구현·배포 완료를 뜻하지 않는다.

## 기술 선택

권장안은 Next.js App Router·TypeScript·CSS/SVG 중심 모션과 Supabase Auth·Postgres·Storage다. Vercel이 애플리케이션을 실행하고 Supabase가 영속 데이터를 보관한다. 관계형 작품·미디어·승인 상태를 함께 관리하고 접근 규칙을 데이터베이스에서 강제하기 편하다.

대안은 Next.js와 Firebase Auth·Firestore·Storage다. 같은 기능을 구현할 수 있으나 작품 필터와 미디어 공개 승인에 필요한 문서 구조·보안 규칙을 별도로 설계해야 한다. 기존 서비스가 없는 현재 상태에서는 Supabase를 기본안으로 삼는다. 추가 모션 라이브러리는 CSS와 SVG만으로 부족한 경우에만 도입한다.

## 방문자 화면

공개 경로 `/` 하나에서 모든 작품을 탐색한다. 헤더의 분야 메뉴는 페이지 내 섹션으로 이동한다. 작품 상세와 이미지 확대는 접근 가능한 대화상자로 열고 닫으며, 초점 복귀·Escape 닫기·키보드 탐색을 지원한다. 관리자 경로 `/admin`은 방문자용 콘텐츠 페이지와 별도로 둔다.

크림색 종이 배경, 짙은 잉크색 글자, 절제된 금빛·보랏빛 포인트를 사용한다. 실제 작품이 장식보다 시각적으로 우선한다. 제공받지 않은 작품·사진·연주를 지안이의 실제 창작물로 표시하지 않는다. 초기 예시는 명확히 예시로 표시하고 관리자에서 교체할 수 있게 한다.

랜딩페이지 순서는 다음과 같다.

1. 즉시 조작 가능한 헤더와 2~3초 이내 Hero: 별빛 → 궤도 → 작품 → 연결선 → 제목 → 부제. 세션 내 반복 방문에는 인트로를 생략한다.
2. 대표 작품 별자리: 작품 선택으로 미리보기·상세 열기, 분야별 위치·연결선 변화, 데스크톱의 미세한 깊이 반응과 모바일 터치 지원. 같은 작품의 일반 목록을 항상 제공한다.
3. 문학, 과학·수학, 미술, 음악, 발레 섹션: 각각 글 구절 순차 등장, 빛의 경로·도형, 종이·캔버스 등장, 재생 중 파형, 곡선 궤적을 사용한다. 모든 분야에 공통 색상·속도 규칙을 적용한다.
4. 분야 필터·연도별 타임라인과 작품 목록. 작품이 없을 때는 빈 상태를 보여 준다.
5. 작품 상세: 원본 비율을 지키는 이미지, 작품 설명, 별도 실제 작품 오디오 플레이어와 사용자가 재생하는 YouTube 영상.

카드·메뉴·필터·팝업 전환은 150~300ms를 기준으로 한다. 실제 작품 위에 지속적인 장식을 겹치지 않는다. 모션·사운드 자원이 없어도 텍스트와 일반 작품 목록을 사용할 수 있다.

## 사운드와 접근성

최초 접속 시 모든 소리는 OFF다. 이후 저장된 설정이 있어도 새 페이지에서 사용자가 재생을 허용하는 조작을 하기 전에는 오디오를 시작하지 않는다. 헤더에서 전체 ON/OFF, 배경 음악·효과음 개별 제어, 볼륨을 제공한다. 개별 설정·볼륨·모션 설정을 로컬에 보관하며 저장이 차단되면 메모리 설정으로 계속 동작한다.

기본 테마는 Web Audio로 직접 구성하는 10~20초의 부드러운 피아노·벨·현악 계열 선율이다. 제삼자 음악이나 실제 지안이 연주라고 표시하지 않는다. 선택·분야 이동·별자리·타임라인·등록 성공·스캔 완료의 효과음은 실제 해당 동작이 있는 경우에만 짧게 재생한다. 존재하지 않는 스캔 기능은 이 추가 지시서만으로 새로 가정하지 않는다.

음악을 켜기 전에는 AudioContext와 음악 파일을 불필요하게 로드하지 않는다. 실제 작품 오디오·영상 재생 시 장식 배경 음악을 중단한다. YouTube IFrame Player API의 실제 재생 이벤트를 이용하고 메시지 발신 출처를 검증한다. 탭 비활성·페이지 이탈·화면 밖 미디어는 재생을 중단하며 탭 복귀만으로 자동 재개하지 않는다. 오디오 재생 중에만 실제 신호를 이용한 파형을 표시한다.

`prefers-reduced-motion`과 화면 내 모션 최소화 설정을 모두 존중한다. 줄인 모션에서는 인트로·시차·반복 장식을 생략하고 콘텐츠는 그대로 제공한다. 모바일·저사양 환경에서는 별과 배경 효과의 수를 줄인다. 인터랙션은 hover에 의존하지 않고 버튼·키보드·터치로 동작한다. 이미지 영역 크기를 미리 확보하고 화면 밖 미디어는 지연 로딩한다.

## 관리자와 데이터

Supabase 계정으로 로그인한 뒤 서버가 관리자로 확인한 사용자만 관리 기능에 접근한다. 공개 회원가입이나 이메일 주소만 비교하는 관리자 판정은 사용하지 않는다. 로그인 화면 노출 여부와 무관하게 데이터베이스 RLS 및 저장소 정책으로 쓰기를 보호한다. 최초 관리자 계정은 운영자가 Supabase에서 만들고 신뢰할 수 있는 SQL 절차로 관리자 권한을 부여한다. 브라우저가 스스로 권한을 부여할 수 없다.

관리자는 작품 생성·편집·삭제·미리보기·공개 승인, 분야·연도·대표 작품 순서, 배경 이미지, 작품별 모션, 모션 강도, 테마 음악, 효과음 허용, 작품 오디오와 YouTube 링크, 기본 테마 복원을 관리한다. 삭제·복원은 확인 절차를 거친다. 실제 재생 매체의 사용 권한을 확인하는 항목을 둔다.

주요 데이터는 `works`(제목·분야·연도·설명·공개 상태·대표 순서·모션 설정), `media`(작품 연결·파일 경로·종류·공개 승인·권리 확인), `site_settings`(배경·테마 음악·효과음·모션 강도), `admin_users`(관리자 사용자 ID)다. 공개 요청에는 공개 승인된 작품·미디어만 반환한다. 설정 역시 공개에 필요한 필드만 노출한다.

원본 업로드는 비공개 Storage에 저장하고 재인코딩하지 않는다. 확장자·MIME·허용 용량·경로를 검증하고 실패를 화면에 표시한다. 이미지 최적화는 별도 전달 경로로 처리한다. 승인 전 파일은 관리자에게만 짧은 유효기간의 서명 URL을 제공한다. 공개 승인을 취소한 자료도 비공개로 되돌릴 수 있도록 공개 버킷 복사 대신 승인 상태를 재확인하는 미디어 접근 경로를 사용한다. 파일을 Vercel의 로컬 디스크에 영구 저장하지 않는다.

서버와 클라이언트 코드를 분리하고 관리자 비밀키를 브라우저 번들에 포함하지 않는다. 저장이 실패했을 때 성공으로 표시하거나 브라우저 로컬 상태를 실제 서버 저장처럼 안내하지 않는다.

## 구성 전 준비 상태와 오류 처리

실제 작품 파일과 Supabase 프로젝트 설정은 아직 없다. 연동 전에도 랜딩페이지와 명시적인 예시를 실행할 수 있도록 한다. 관리 화면에는 서버 연결 필요 상태를 표시하고 가짜 로그인·가짜 저장을 제공하지 않는다. 클라우드 설정은 환경변수 이름과 존재 여부만 조사한 뒤 실제로 부족한 항목만 요구한다. 비밀값은 채팅·설계서·저장소에 기록하지 않는다.

Vercel과 로컬 개발에 필요한 Supabase URL·공개 키 등은 구현에서 선택한 공식 SDK 방식에 맞춰 `.env.example`에 이름만 기록한다. 스키마와 RLS 설치 SQL, 최초 관리자 등록 절차, Vercel 환경변수 설정은 운영 문서로 제공한다. 실제 서비스 연결 검증과 설정 없이 검증한 범위는 결과에서 구분한다.

## 구현 순서와 검증 기준

1. Next.js 기본 구조, 반응형 단일 랜딩, 일반 작품 목록·필터·상세, 기본 모션과 명시적 사운드 제어를 구현한다.
2. Supabase 스키마·RLS·인증, 관리자 설정과 비공개 업로드·승인, 실제 데이터 조회를 연결한다.
3. 별자리·분야별 모션·타임라인·파형·YouTube와 배경 음악의 조정, 모션 품질 조절을 통합한다.
4. 타입 검사·프로덕션 빌드와 핵심 동작 테스트를 실행한다. 브라우저에서 모바일·데스크톱·키보드·모션 최소화, 첫 접속 무음·명시적 재생·설정 유지·영상 재생 시 배경 음악 중단·탭 비활성 중단·리소스 누락 상태를 확인한다.
5. Supabase가 연결되면 비로그인 쓰기 거부, 비관리자 쓰기 거부, 관리자 저장, 비공개 미디어 접근 거부, 승인과 취소를 실제 연동으로 검증한다. 연결되지 않았다면 이 항목들을 미검증으로 보고한다.

개발 환경 설치와 앱 시작을 실제 실행하고, 필요한 설치 스크립트와 서비스 시작·준비 확인 지침을 클라우드 환경 초안에 저장한다. 이 클라우드 작업은 이미 격리되어 있으므로 기존 `/workspace/jian`을 사용하고 별도 Git worktree를 만들지 않는다. Vercel 배포 가능한 결과물과 운영 절차를 준비하되 실제 배포·클라우드 환경 게시 여부는 확인된 사실만 보고한다.

## 검토 범위

사용자 답변에 근거한 기본안은 “방문자용 단일 페이지 + 별도 관리자 경로 + Next.js/Supabase + Vercel”이다. 본 설계 검토 후 구현 계획을 작성한다. 실제 작품 제공 전에는 예시임을 표시하고, 외부 서비스 설정 전에는 관리자 저장·공개 승인 연동 완료를 주장하지 않는다.
